Overview

The recommended setup

Pick up your phone while away and continue programming with Codex CLI on your home or work Mac. Use iPhone as the Mac's secure remote terminal, rather than a messaging bot or another AI platform wrapped around it.

The final setup is: install Tailscale and Termius on iPhone, install Tailscale on Mac, enable Remote Login, and persist Codex CLI sessions with tmux.
Usernames, domains, Tailscale IPs, and Host names here are placeholders. Keep actual values in your secrets repository or private configuration; do not write them into this repository.

Problems this setup solves

  • No public exposure of the SSH port.
  • No lost Codex session when the phone backgrounds the app or switches networks.
  • Control your actual local repository, rather than a replica on a third-party platform.
  • A short connection path that is easy to troubleshoot.

Outside this setup

  • An asynchronous bot that accepts a Lark message and dispatches tasks in the background.
  • A hosted service where cloud Codex holds your working directory.
  • Remote desktop control of the iTerm2 graphical interface.
Architecture

The complete architecture

The path has five core components, each with one clear responsibility. This keeps the setup reliable and makes failures easier to locate.

iPhone

Your remote entry point: starts connections, accepts commands, and displays Codex output. It does not execute the programming tasks itself.

Tailscale

Places iPhone and Mac in the same private tailnet. It establishes secure connectivity; it does not provide terminal interaction.

Termius

The iPhone SSH client. It connects to the Mac's SSH service over Tailscale and provides terminal interaction.

macOS Remote Login

The Mac's built-in SSH server. Once enabled, it accepts tailnet SSH connections and opens the corresponding user's shell.

tmux + Codex CLI

tmux keeps sessions running across remote disconnections; Codex CLI understands, modifies, tests, and executes code.

Principle

How the components work

1. Tailscale connects the network

Tailscale uses WireGuard-based networking to place devices in one private network. After iPhone and Mac join the same tailnet, the phone can reach the Mac through its Tailscale IP or MagicDNS name, such as YOUR_MAC_TAILNET_FQDN.

2. SSH establishes the terminal

Termius starts an SSH connection and macOS Remote Login accepts it. After authentication, you get that user's actual Mac shell, rather than a terminal wrapped by an intermediary agent.

3. tmux keeps sessions alive

iOS frequently backgrounds apps, locks the screen, or changes networks. Without tmux, an SSH disconnection commonly terminates the current terminal process. With tmux, Codex continues in a background session; the next connection only needs to attach again.

4. Codex CLI stays on Mac

Repositories, dependencies, test tools, git state, SSH keys, and environment variables stay on your Mac. The phone is only a remote entry point, so local and remote development experiences are almost identical.

For actual programming, a native terminal path is shorter, more transparent, and preserves more context than WeChat messages → intermediary agent → Codex.
Flow

How input and output travel

This path carries a standard SSH terminal byte stream, rather than business-message packets. After you tap a Host, control and output flow in this order.

  1. Open Tailscale on iPhone and confirm connection to your tailnet.
  2. Tap a saved Termius Host, such as codex-remote-host.
  3. Termius connects over Tailscale to SSH at YOUR_MAC_TAILNET_FQDN:22.
  4. Mac Remote Login receives the connection and checks the username and SSH key.
  5. After authentication, macOS starts a shell session for that user.
  6. A startup script such as ~/bin/codex-remote runs automatically after login.
  7. The script checks for a tmux session named codex: create one if absent, or attach if present.
  8. tmux starts or displays the existing Codex CLI. Phone input becomes terminal standard input on Mac; Codex output returns over SSH to iPhone.
iPhone
  -> Tailscale tailnet
  -> SSH(Termius)
  -> macOS Remote Login
  -> login shell
  -> ~/bin/codex-remote
  -> tmux session: codex
  -> Codex CLI
  -> stdout / stderr
  -> SSH back to iPhone
Mac Setup

Set up the Mac

Mac executes the work: it runs Tailscale, exposes SSH, keeps tmux sessions alive, and runs Codex CLI in those sessions.

Step 1: Install and sign in to Tailscale

Install the official Tailscale Mac client, sign in, and confirm it has joined the target tailnet.

Step 2: Enable Remote Login

In System Settings, open General -> Sharing -> Remote Login and allow only your own account.

If code lives in protected locations such as Desktop or Documents, enable Allow full disk access for remote users as needed.

Step 3: Install tmux

Install through Homebrew to retain sessions after disconnecting and reconnecting.

brew install tmux

Step 4: Verify Codex CLI runs directly

First confirm in a local terminal that codex is installed, logged in, and works in the target repository.

Step 5: Prepare an attach script

The script creates a tmux session and starts Codex if no session exists; otherwise, it attaches to the existing session.

mkdir -p ~/bin

cat > ~/bin/codex-remote <<'EOF'
#!/bin/zsh
set -e

SESSION="codex"
PROJECT="$HOME/code/your-repo"

if ! tmux has-session -t "$SESSION" 2>/dev/null; then
  tmux new-session -d -s "$SESSION" -c "$PROJECT" "codex"
fi

exec tmux attach -t "$SESSION"
EOF

chmod +x ~/bin/codex-remote

Step 6: Optional local alias

To enter the same session quickly from Mac, add an alias to ~/.zshrc.

alias cdx='~/bin/codex-remote'
iOS Setup

Set up the iPhone

iPhone has two roles: joining the tailnet and acting as the SSH terminal. Use Tailscale + Termius.

Step 1: Install and sign in to Tailscale

  • Install Tailscale from the App Store.
  • Sign in with the same account as Mac or join the same organization's tailnet.
  • Confirm your Mac appears in the Tailscale device list.

Step 2: Install Termius

  • Install Termius from the App Store.
  • Import or generate your SSH key.
  • Ensure the corresponding public key is in Mac ~/.ssh/authorized_keys.

Step 3: Create a Termius Host

Use the following configuration to enter your Codex session by tapping the Host.

Name: codex-remote-host
Address: YOUR_MAC_TAILNET_FQDN
Port: 22
Username: YOUR_MAC_USER
Authentication: SSH Key
Startup Snippet: ~/bin/codex-remote

Step 4: Verify the first connection

With correct configuration, opening the Host enters or attaches directly to the Codex session on your Mac instead of displaying an ordinary shell prompt.

Routine

Daily workflow

Before leaving
Confirm Mac is powered on, connected to the network, and online in Tailscale, and that codex runs locally.
Start work
Open Tailscale on iPhone, then Termius, and tap the codex-remote-host Host.
Resume tasks
If Codex is still running, return to its existing tmux session; otherwise a new session is created automatically.
Step away
Exit or background the iPhone app. Disconnecting SSH does not terminate Codex inside tmux.
Change projects
Create separate scripts or tmux sessions for repositories, such as codex-work and codex-side.

Security

Security boundaries and practices

Clear security boundaries are a central advantage. Without public SSH exposure, the attack surface is much smaller than publicly opening port 22 with password login.

Boundaries to retain

  • Do not forward router ports or expose port 22 to the public internet.
  • Allow only the specified account in Remote Login, rather than All users.
  • Prefer SSH keys; do not rely on password login long-term.
  • Codex runs locally; code and credentials stay on Mac.

Further hardening

  • Use finer Tailscale ACLs to allow only your phone to access this Mac.
  • Use independent sessions and read-only inspection scripts for different repositories.
  • Consider mosh or stronger terminal persistence as needed.
FAQ

Frequently asked questions

  1. Does Mac need Termius too? No. Termius is the iPhone SSH client; Mac needs only Tailscale, Remote Login, tmux, and Codex CLI.
  2. Why not control iTerm2 through remote desktop? Phone screens are small and remote desktop adds latency. Text terminals are more reliable and clearer than graphical remote desktop.
  3. Why not WorkBuddy or a Lark bot? Those suit message-based task dispatch and automation; native SSH terminals better support sustained programming.
  4. What happens without tmux? Backgrounding iPhone or losing the network can disconnect Codex. tmux is the key session persistence layer.
  5. What if Mac sleeps? iPhone cannot connect to an asleep, offline Mac. Keep Mac powered on and connected during use.
