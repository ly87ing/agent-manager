Remote Codex Blueprint

用 iPhone 远程进入你 Mac 上的 Codex CLI

这是一条最短、最稳、最适合长期编程的链路。手机不是把任务发给中间代理，而是通过 Tailscale 接入你的私有网络，借助 SSH 直接进入 Mac 的 shell， 再由 tmux 托管会话，让 Codex CLI 一直运行在你自己的机器上。

iPhone 负责入口 Tailscale 负责私网连通 Termius 负责 SSH 终端 tmux 负责会话保活 Codex CLI 负责编程任务
Step 1

iPhone + Tailscale

手机先加入同一个 tailnet。它获得一条只对你的私网可见的访问路径，不需要公网暴露 Mac 的 22 端口。

Step 2

Termius 发起 SSH

你在 Termius 点一下保存好的 Host，连接到 YOUR_MAC_TAILNET_FQDN。

Step 3

Mac Remote Login

macOS 的 Remote Login 接收 SSH，会话落到你自己的用户 shell。

Step 4

tmux 接管会话

连接后自动附着到 codex session；断网、锁屏、切应用都不会杀掉正在运行的任务。

Step 5

Codex CLI 继续工作

你看到和控制的是 Mac 本机上的真实终端上下文，包括仓库、测试、日志和文件系统。

Overview

一句话方案

你要实现的是“在外面拿起手机，就能继续使用家里或公司那台 Mac 上的 Codex CLI 做编程任务”。最合适的链路不是消息机器人，也不是另一个 AI 平台包一层，而是把 iPhone 变成那台 Mac 的安全远程终端入口。

最终方案固定为：iPhone 上装 Tailscale 和 Termius，Mac 上装 Tailscale，开启 Remote Login，使用 tmux 持久化 Codex CLI 会话。
文中的用户名、域名、Tailscale IP 和 Host 名都应视为占位符。真实值请保存到你的 secret 库或私密配置中，不要写回当前仓库。

这套方案解决什么问题

  • 不在公网暴露 SSH 端口。
  • 手机掉后台或网络切换时，不丢失 Codex 会话。
  • 你控制的是本机真实仓库，不是第三方平台里的镜像环境。
  • 链路短，出问题时容易排查。

这套方案不是什么

  • 不是“飞书发一句话，后台自动派任务”的异步机器人。
  • 不是“云端 Codex 替你保管工作目录”的托管方案。
  • 不是“远程桌面控制 iTerm2 图形界面”。
Architecture

完整架构拆解

这条链路只有五个核心组件。每个组件只有一个明确职责，所以整体非常稳定，也更容易知道哪里出了问题。

iPhone

你的远程操作入口。负责发起连接、输入命令、查看 Codex 输出。它不执行编程任务本身。

Tailscale

负责把 iPhone 和 Mac 放进同一个私网 tailnet。它解决的是“怎么安全连上去”，不是“怎么操作终端”。

Termius

iPhone 上的 SSH 客户端。它通过 Tailscale 网络连接到 Mac 的 SSH 服务，并负责你的终端交互体验。

macOS Remote Login

Mac 自带的 SSH server。开启后，它会接收来自 tailnet 内部的 SSH 连接，并把你送进对应的用户 shell。

tmux + Codex CLI

tmux 负责让远程会话不中断，Codex CLI 负责真正的代码理解、修改、测试与执行。

Principle

原理是怎样运作的

1. Tailscale 做的是网络层打通

Tailscale 基于 WireGuard 思路把设备放进同一个私网。你的 iPhone 和 Mac 都登录同一个 tailnet 后， iPhone 就能通过 Tailscale IP 或 MagicDNS 名称访问 Mac，例如 YOUR_MAC_TAILNET_FQDN。

2. SSH 做的是终端会话建立

Termius 发起 SSH 连接，macOS 的 Remote Login 接受该连接。认证通过后，你拿到的是 Mac 上那个用户的 shell，而不是某个中间代理包装出来的终端。

3. tmux 做的是会话保活

iOS 很容易切后台、锁屏或切换网络。没有 tmux 时，SSH 断开通常就意味着当前终端进程也会终止。 用 tmux 后，Codex 在后台 session 里持续运行，下一次连接只需要重新 attach。

4. Codex CLI 始终运行在 Mac 本机

仓库、依赖、测试工具、git 状态、SSH key、环境变量，都仍然在你的 Mac 上。手机只是远程入口，这意味着本机开发体验和远程开发体验几乎是一致的。

这也是为什么不推荐把这件事先做成“微信消息 -> 中间代理 -> 再调 Codex”的原因：对真正的编程任务来说，原生终端链路更短、更透明、上下文也更完整。
Flow

中间消息是如何交互的

整个全链路里，真正传输的不是“业务消息包”，而是标准 SSH 终端字节流。你点开 Host 之后，控制和输出按下面顺序流动。

  1. iPhone 打开 Tailscale，确认已经接入你的 tailnet。
  2. 你在 Termius 点击一个预先保存好的 Host，例如 codex-remote-host。
  3. Termius 通过 Tailscale 网络，向 YOUR_MAC_TAILNET_FQDN:22 发起 SSH 连接。
  4. Mac 上的 Remote Login 收到连接请求，校验用户名和 SSH key。
  5. 认证通过后，macOS 为该用户启动一个 shell 会话。
  6. 登录后自动执行一个启动脚本，例如 ~/bin/codex-remote。
  7. 脚本检查是否存在名为 codex 的 tmux session；没有就创建，有就直接附着。
  8. tmux 内部已经启动或继续显示 Codex CLI；你接下来在手机上的输入，会变成 Mac 上终端的标准输入，Codex 的输出再经 SSH 流回 iPhone。
iPhone
  -> Tailscale tailnet
  -> SSH(Termius)
  -> macOS Remote Login
  -> login shell
  -> ~/bin/codex-remote
  -> tmux session: codex
  -> Codex CLI
  -> stdout / stderr
  -> SSH 回传到 iPhone
Mac Setup

Mac 上需要做什么

Mac 是执行端。它负责运行 Tailscale、暴露 SSH、保持 tmux 会话，并在这个会话里长期运行你的 Codex CLI。

步骤 1：安装并登录 Tailscale

在 Mac 上安装 Tailscale 官方客户端，登录你的账号，并确认它已经加入目标 tailnet。

步骤 2：开启 Remote Login

打开系统设置，进入 General -> Sharing -> Remote Login，只允许你自己的账号登录。

如果你的代码目录在 Desktop 或 Documents 等受保护路径，可按需打开 Allow full disk access for remote users。

步骤 3：安装 tmux

建议通过 Homebrew 安装，确保断线重连时会话仍然存在。

brew install tmux

步骤 4：确保 Codex CLI 可直接运行

先在本机终端里确认 codex 已安装、已登录、能在目标仓库正常运行。

步骤 5：准备一键附着脚本

这个脚本的作用是：如果 tmux session 不存在，就创建并启动 Codex；如果已存在，就直接附着进去。

mkdir -p ~/bin

cat > ~/bin/codex-remote <<'EOF'
#!/bin/zsh
set -e

SESSION="codex"
PROJECT="$HOME/code/your-repo"

if ! tmux has-session -t "$SESSION" 2>/dev/null; then
  tmux new-session -d -s "$SESSION" -c "$PROJECT" "codex"
fi

exec tmux attach -t "$SESSION"
EOF

chmod +x ~/bin/codex-remote

步骤 6：可选，本机别名

如果你也想在 Mac 本机快速进入同一个会话，可以在 ~/.zshrc 里加一条别名。

alias cdx='~/bin/codex-remote'
iOS Setup

iPhone 上需要做什么

iPhone 只承担两个角色：接入 tailnet，以及作为 SSH 终端使用。推荐组合是 Tailscale + Termius。

步骤 1：安装并登录 Tailscale

  • 在 App Store 安装 Tailscale。
  • 登录与 Mac 相同的账号或同一个组织下的 tailnet。
  • 确认在 Tailscale 设备列表中能看到你的 Mac。

步骤 2：安装 Termius

  • 在 App Store 安装 Termius。
  • 导入或生成你的 SSH key。
  • 确保对应公钥已经在 Mac 的 ~/.ssh/authorized_keys 里。

步骤 3：在 Termius 新建 Host

推荐配置如下。这样你以后只需要点一下 Host 就能进入 Codex 会话。

Name: codex-remote-host
Address: YOUR_MAC_TAILNET_FQDN
Port: 22
Username: YOUR_MAC_USER
Authentication: SSH Key
Startup Snippet: ~/bin/codex-remote

步骤 4：首次连接验证

点开这个 Host 后，如果一切配置正确，你看到的不会是普通 shell 提示符，而是直接进入或附着到你 Mac 上的 Codex 会话。

Routine

日常怎么使用

出门前
确认 Mac 开机、联网、Tailscale 在线，且本机可以正常运行 codex。
开始工作
iPhone 打开 Tailscale，随后打开 Termius，点一下 codex-remote-host Host。
继续任务
如果此前的 Codex 还在跑，你会重新回到原来的 tmux 会话；如果没有，会自动创建新会话。
临时离开
直接退出或把 iPhone 切后台即可。SSH 断开不会终止 tmux 里的 Codex。
切换项目
可以为不同仓库准备不同脚本或不同 tmux session，例如 codex-work、codex-side。

多项目脚本示例

#!/bin/zsh
set -e

SESSION="codex-work"
PROJECT="$HOME/work/project-a"

if ! tmux has-session -t "$SESSION" 2>/dev/null; then
  tmux new-session -d -s "$SESSION" -c "$PROJECT" "codex"
fi

exec tmux attach -t "$SESSION"
Security

安全边界与推荐做法

这套方案的核心优势之一就是安全边界清晰。只要你不主动暴露公网 SSH 端口，它的攻击面会比传统“公网开放 22 端口 + 密码登录”小很多。

建议保留的边界

  • 不要做路由器端口映射，不把 22 端口暴露到公网。
  • Remote Login 只允许指定账号，而不是 All users。
  • 优先使用 SSH key，不要长期依赖密码登录。
  • Codex 仍在本机运行，代码和凭证不离开 Mac。

后续可加固的项

  • 给 Tailscale 开启更细的 ACL，只允许你的手机访问这台 Mac。
  • 为不同仓库设置独立会话和只读检查脚本。
  • 视需要使用 mosh 或更强的终端保活策略。
FAQ

常见问题

  1. Mac 端也要装 Termius 吗？ 不需要。Termius 只是 iPhone 上的 SSH 客户端，Mac 端只需要 Tailscale、Remote Login、tmux 和 Codex CLI。
  2. 为什么不直接用远程桌面控制 iTerm2？ 因为手机屏幕小、远程桌面延迟高，而且文本终端比图形远程桌面更稳、更清晰。
  3. 为什么不用 WorkBuddy 或飞书机器人？ 那些方案更适合消息派单或自动化任务，不如原生 SSH 终端适合持续编程。
  4. 没有 tmux 会怎样？ iPhone 切后台或网络断开时，Codex 很可能跟着断。tmux 是整个方案里最关键的保活层。
  5. 如果 Mac 休眠了怎么办？ iPhone 无法连接到已休眠且离线的 Mac，所以实际使用时要保证 Mac 处于开机联网状态。

这份页面的目标不是介绍所有可能的远程开发方案，而是固定出一条最适合你当前环境的主路径：iPhone + Tailscale + Termius -> Mac -> tmux -> Codex CLI。
