# Rust 原生桌面任务书

当前执行分支为 `rust`。本文定义实施与验收要求，产品行为以 [GUI-REDESIGN.md](GUI-REDESIGN.md) 为准。旧 [GUI-ARCHITECTURE-PROPOSAL.md](GUI-ARCHITECTURE-PROPOSAL.md) 和 [GUI-STANDALONE-PLAN.md](GUI-STANDALONE-PLAN.md) 仅为历史记录，不再约束新版实现。

## 最终目标

交付独立运行的 Tauri 桌面应用：Rust 原生后端统一管理本地 SQLite、助手生命周期、Skills、MCP、规则与 Hooks。无 Python、旧 Shell 引擎和源码目录依赖。新建助手主要填写所需命令；资源库和每个助手内的资源都提供明确管理动作。

## 已确定的要求

- 用户本机修改以 `native-manager.db` 为准；偏好用 `settings.json`；资源正文以不可变文件保存，分配记录引用明确版本。
- 内置模板按官方来源核对，支持用户修改；保存不执行；不以 brew 统一代替官方默认。
- 集合和逐助手资源分别支持添加、删除、更新、启用、禁用；禁用保留选择与版本，删除分配不删除其他助手使用。
- 更新资源库不自动升级已有分配；新资源不自动加入所有助手；同名、外部修改和共享目标不能静默覆盖。
- 预览、取消及演练零写入；失败保留可解释的实际状态，不能以数据库 enabled 或命令 exit 0 代替验证。
- Python 已停止维护并获准清理，不要求旧命令兼容、双实现逐字节一致、三层 JSON 或旧 profile 同步继续存在。

## 实施方式与授权

主审负责设计、审查、独立验收和提交；具体代码、测试与构建接线由实施标签页完成。优先 agy YOLO，明确额度耗尽后使用 kimi-ly YOLO；两者均耗尽时使用 Codex Luna（`gpt-5.6-luna`）。切换必须记录实际原因，不把工具启动成功当作模型执行成功。

每次交给实施者一个可验证的闭环，明确可改文件、公共接口和反例；共享接口只设一个负责人。实施者交回后停笔，主审核对最终 diff 和实际结果。原有候选允许舍弃或重做，不能为了保留候选而扩展兼容层。

用户已授权分批提交、推送远程 `rust` 分支及清理退役 Python。先审查整个待推送范围，再核对本地、跟踪分支、远程提交一致。禁止混入无关修改或重写历史；创建 tag、Release、上传安装包及修改远程发布凭据不属于当前授权。

## 阶段与验收

| 阶段 | 交付闭环 | 必须通过的验收 |
| --- | --- | --- |
| 1 原生核心 | Rust 库与 CLI 读写 SQLite，Tauri 直接调用 | 保存与重启读回；取消和演练零写入；损坏库、外来库、符号链接保护；并发初始化不丢数据 |
| 2 助手 | 模板、自定义命令和安装/升级/卸载 | 无需改代码新增；命令可修改；超时/大输出处理；执行后核对实际二进制与来源 |
| 3 Skills | 本地与 Git 集合、版本及分配 | 两助手五种操作互不影响；集合暂停恢复保留逐项选择；上游删除不破坏已用版本 |
| 4 其他资源 | MCP stdio/HTTP、规则与 Hooks 的资源库与分配 | 各支持格式真实写入并回读；未知字段保留；外部修改拒绝；失败恢复不覆盖后续修改 |
| 5 Python 清理 | 旧代码、脚本、测试、CI、打包及文档引用退役 | 不遗留隐式 Python 调用；有效安全检查转入 Rust；有效资源正文和用户数据保留 |
| 6 独立桌面 | 最终提交构建的安装包 | 无解释器/源码依赖；真实界面操作及重启；窗口、焦点、错误提示与实际结果一致 |

先完成阶段内最小闭环，再扩大范围。清理与行为变更分别提交。可以提前清点退役范围，但不能在替代功能尚未验收时宣称原生链路已完整。

## 验证规则

先运行定向用例，再运行对应 Rust 或前端完整检查。测试应覆盖数据和文件效果，不只匹配提示文案。使用隔离 HOME、应用数据目录、测试助手路径和替身命令；不要执行真实安装或清理用户配置。

旧 Python 专属测试随退役代码删除；仍适用的原子写、范围隔离、秘密保护与失败反例迁入 Rust。不得为通过测试放松有效断言，也不得为旧文案测试恢复废弃要求。未运行、未覆盖和失败项据实列明。

当前平台先验收 macOS；Linux、Windows、签名和真实更新分别核对，不以本机结果推断全平台通过。独立包的 Python 禁用、源码隔离必须实测，mock 页面和单次构建不能替代。
