# Agent Manager 本地管理重设计

状态：2026-09-08 按用户最新要求调整为 Rust 原生桌面管理。保留 Tauri 界面，管理后端直接使用 Rust；停止沿用 Python 引擎、脚本适配器及 Python 运行时打包。此前已提交的 Python 能力和隔离测试属于旧路线，不能作为新版完成证据。当前正在实现原生核心及 Agent、Skills、MCP 操作，完整桌面验收尚未完成。

用户在一个本地应用里添加 Agent、Skill、MCP 和规则，选择哪些 Agent 使用，执行安装或更新，看到实际结果。本机调整存入 SQLite；日常操作无需理解 Git、策略层、覆盖定义或同步命令。

设计按四个问题展开：数据保存在哪里，Agent 如何安装升级，Skill 如何管理与分配，MCP 等配置如何采用相同的操作方式。技术迁移与验收放在最后。

## 本机数据由应用持有

沿用桌面版已有的应用数据目录，GUI 与 CLI 使用同一个目录解析规则。设置页提供“打开数据目录”；无需为了隐藏目录再迁移一次位置。

| 数据 | 存储方式 | 修改入口 |
| --- | --- | --- |
| Agent 定义、用户命令、集合、资源、分配关系、版本选择 | `native-manager.db`，SQLite | GUI/CLI 经同一 Rust 库写入 |
| 窗口、主题、语言等设备偏好 | `settings.json` | 设置页 |
| Skill 文件和下载内容 | 数据目录内的资源目录，数据库记录版本及路径 | 资源管理操作 |
| Agent 实际读取的 Skill、MCP、规则 | Agent 官方支持的位置和格式 | 引擎按明确范围生成 |
| 内置 Agent 模板 | 应用包内只读文件 | 随应用发布更新 |
| 真实凭证和敏感配置 | 外部私有 `secrets/` 仓库 | 应用只保存引用、运行时注入 |

SQLite 管理集合、资源和分配关系，约束重复记录并事务化修改。少量设备偏好继续使用 JSON；Skill 正文保留文件形态。隐藏文件本身不提供加密。

内置模板只提供可选默认值。添加 Agent 时复制模板成为本机记录；应用升级不得覆盖用户命令、复活删除项或重新启用资源。模板变化展示差异，由用户选择采用；“恢复官方命令”是明确的编辑操作。

第一版无默认云端同步、Git profile 或三层策略编辑入口。不自动读取旧项目配置或旧数据库，不把开发者机器配置作为安装包默认值。后续分享需显式选择导出非敏感配置，不直接上传数据库或机器路径。

## Agent：填必要命令即可管理安装和升级

主列表显示名称、安装状态、当前版本、实际安装方式，以及“安装 / 升级 / 卸载 / 编辑命令”。详情分为“安装与升级、Skills、MCP、规则与 Hooks”。

“添加 Agent”提供“从内置模板添加”和“自定义 Agent”。日常表单不要求编辑 JSON：

| 字段 | 要求与作用 |
| --- | --- |
| 名称 | 必填，内部 ID 自动生成 |
| 命令名或可执行文件路径 | 必填，定位实际安装 |
| 版本检查命令 | 默认建议 `<命令名> --version`，允许修改；失败显示“版本未知” |
| 安装命令 | 要管理安装时必填 |
| 升级命令 | 要管理升级时必填 |
| 卸载命令 | 可选；未填则显示“不支持自动卸载” |
| 适用系统与 Shell | 默认当前系统，可分别配置 macOS、Linux、Windows |
| 工作目录、环境变量引用 | 高级选项；敏感值只引用外部 secrets |

只填写生命周期命令，就能接入安装与升级。Skill 和 MCP 另需发现目录/方式、配置格式或官方管理命令。内置模板预填；自定义 Agent 选择已支持的适配方式。未知格式显示“尚未配置支持”，不能声称几条安装命令就能兼容任意 Agent 的配置。

保存只保存定义。安装、升级、卸载分别执行；用户能查看、修改并测试命令。“测试命令”明确会运行该命令，不在保存或输入时自动执行。

### 默认方式来自官方，升级遵循实际安装来源

| Agent | 新安装默认方式 | 升级依据 |
| --- | --- | --- |
| Claude Code | 官方明确推荐的原生安装器 | 原生安装支持自动更新，手动使用 `claude update`；展示自动更新归属，避免重复调度 |
| Codex | 当前官方 CLI 页面首先提供的独立安装器 | 当前页面的 Update Codex 使用同一安装脚本，模板遵循该方式 |
| 自定义 Agent | 用户填写的安装命令 | 用户填写的升级命令 |

macOS/Linux 官方命令分别为 `curl -fsSL https://claude.ai/install.sh | bash` 和 `curl -fsSL https://chatgpt.com/codex/install.sh | sh`。Windows 不能复用 POSIX Shell 字符串；Claude 模板采用官方平台命令，Codex 的 Windows 原生安装尚未核实，当前不提供该默认动作。以上安装命令仅核对，未在本机执行。[Claude 官方安装与更新说明](https://code.claude.com/docs/en/setup)、[Codex 官方 CLI 说明](https://developers.openai.com/codex/cli)，2026-09-08 核对。

Homebrew 并非一概不受官方支持；两家的资料都提供该渠道。产品区分“官方推荐”“官方支持”“用户自定义”，不把项目维护者偏好标成官方推荐。模板记录官方链接、核对日期、平台和命令。

已通过 brew/npm 安装的 Agent 默认沿用来源升级。“迁移安装方式”单独展示安装、PATH 冲突及旧安装处理步骤。发现多个版本或来源不明时先选定管理对象，不自动卸载其他版本。移除管理记录与卸载软件是两个动作；卸载不默认删除登录和会话数据。

用户命令按用户权限、所选 Shell 和工作目录执行，不隐式加 sudo。预览展示实际命令；导入资源中的脚本不自动成为用户已授权命令。导入或升级模板不触发执行。

## Skill：集合管理与 Agent 使用情况分开

“Skills”默认打开“集合”，另有“全部技能”。集合详情列技能；Agent 详情的 Skills 标签只展示该 Agent 的分配。矩阵是可选总览，不承担唯一操作入口。

技能行显示名称、来源集合、资源库版本、本 Agent 版本、启用状态和实际生效结果。同名但不同来源是不同资源；发生 Agent 目标名称冲突时展示双方来源并要求选择，不静默覆盖。

### 集合层的五种操作

| 操作 | 明确效果 |
| --- | --- |
| 添加集合 | 输入 Git 地址或本地目录，扫描技能并加入资源库；不自动分配给全部 Agent |
| 更新集合 | 获取新版本并展示新增、变更、删除项；保存到资源库，已有 Agent 仍用原版本 |
| 禁用集合 | 暂停该集合在已分配 Agent 中的使用；保留文件、版本及逐项开关 |
| 启用集合 | 恢复原来已启用的分配；原本禁用的继续禁用，新技能不自动加入 |
| 删除集合 | 展示受影响 Agent，明确删除分配及受管入口，再移除集合记录；不删除本地源目录或上游仓库 |

更新集合后可点击“更新到 Agent…”，勾选目标和变更项。“更新资源库”和“更新所有 Agent”分开。上游删除的技能保留已有版本并标记“来源已删除”，不连带清除现有使用。

本地集合默认导入内容快照，更新时重新扫描；源目录编辑不会直接改变所有 Agent。缓存清理只处理无分配引用的本工具资源，放在设置页独立执行。

### 每个 Agent 内的五种操作

| 操作 | 明确效果 |
| --- | --- |
| 添加技能 | 从资源库选择技能及版本，也可先导入本地技能；添加后默认启用，提交前可取消勾选 |
| 更新技能 | 选择资源库新版本，只更新当前 Agent 的这一个技能 |
| 禁用技能 | 保留分配和版本，撤下该 Agent 可发现的受管入口 |
| 启用技能 | 恢复受管入口；集合禁用时说明原因并提供前往集合的入口 |
| 从此 Agent 删除 | 删除分配和入口；保留资源库、来源集合及其他 Agent 分配 |

“全部技能”也提供添加本地技能、更新资源版本、全局启用/禁用和删除。全局禁用保留逐 Agent 选择；全局删除先列出受影响分配。删除远程集合条目表示本地排除，下次集合更新不复活；“显示已排除技能”中可重新添加。

有效启用要求集合可用、技能未全局禁用、分配存在且启用。界面显示阻止生效的具体原因。“未添加”没有分配关系，与“已禁用”不同。

### 单 Agent 更新需要版本隔离

下载后的 Skill 版本目录不可原地改写。Git 来源以提交与技能内容标识版本，本地来源以内容摘要标识；每个分配引用一个明确版本。更新 Claude 的技能只切换 Claude 入口，Codex 引用不变。可用不可变目录加链接；无法链接的平台使用受管副本并校验内容。

禁用不删除正文。手工安装、其他工具或插件管理的技能先显示“外部管理”，明确导入或接管后才能修改。部分 Agent 共用发现目录：适配器必须验证独立入口或官方排除机制；没有隔离能力时显示“共享目录，暂不支持单独禁用”，不能删除共享入口影响其他 Agent，也不能虚报成功。

停用和更新影响下一次发现或加载，已有会话可能仍持有内容。结果区按适配器提示“新会话生效”或“需要重启”，不把文件落盘等同于运行中的 Agent 已刷新。

## MCP、规则和 Hooks 使用相同的资源与分配模型

MCP 主页面为“服务库”。添加服务填写名称、stdio/HTTP 类型、启动命令与参数或地址、环境变量引用。高级 JSON 按需展开。Agent 详情的 MCP 标签提供“添加服务、更新、启用、禁用、从此 Agent 删除”。

| 范围 | 添加 / 更新 | 启用 / 禁用 | 删除 |
| --- | --- | --- | --- |
| MCP 服务库 | 保存定义新版本；应用到已有分配时另选 Agent | 暂停/恢复已有分配，保留逐 Agent 开关 | 清理确认范围内受管分配，再删除定义 |
| 某个 Agent 的 MCP | 添加服务或采用指定定义版本；覆盖值只影响该 Agent | 写入/撤下该 Agent 的受管服务项 | 只移除该 Agent 的服务项与分配 |
| 规则、Hooks 资源库 | 添加内容/定义、更新版本 | 全局暂停/恢复，不丢失分配选择 | 展示影响范围后移除受管分配与定义 |
| 某个 Agent 的规则、Hooks | 选择资源、更新当前 Agent 的版本 | 撤下/恢复受管内容 | 只移除当前 Agent 分配与受管内容 |

MCP 的“更新配置”和“升级服务程序”分开。本地服务只有明确升级命令才提供程序升级；远程 HTTP 服务无法由本机升级，显示“不适用”。多个 Agent 共用一个程序时，升级程序列出全部受影响 Agent，不冒充单 Agent 升级。

禁用 MCP 不删除凭证，不停止其他 Agent 共用的外部进程。配置成功与连接成功分别显示；读写配置保留非受管键，对外部修改展示差异，避免无提示覆盖。

规则与 Hooks 使用对应 Agent 支持的文件、命令或受管区块。规则来源编辑与生成分离；本仓库分发规则仍从 `agent-rule/rules/src/` 构建，不编辑 dist。Hooks 中可执行代码在添加到 Agent 时展示，保存到资源库不触发运行。普通工具复用生命周期表单；进程组件另用“启动/停止”，不用“启用”代替停止进程。

## 一个操作只有一个明确结果

日常导航为“助手、技能、MCP、规则与 Hooks、操作记录、设置”，默认打开助手。其他工具入口放在设置的“高级管理”内，可进入并返回设置；策略、同步、快照不作为完成添加的必经页面。

单项可逆开关点击后执行，进行中显示“正在禁用”；失败保留实际状态并提供重试。安装、卸载、集合批量变更展示一次影响预览，确认后执行。按钮写明“禁用集合”“从 Codex 删除”，不只写“移除”“同步”。

预览期间只持有草稿，取消后数据库、分配和目标文件均不改变。“保存定义”只保存资源；“添加到 Agent”“启用”等必须应用并回读后才提示成功。

状态区分“未添加、已禁用、正在应用、已生效、应用失败、需重启”。更新状态另列“可更新、未检查”。文件被其他程序改动时显示“外部修改”，展开可查看差异和处理方式。

数据库事务不能回滚外部 Shell 和多个文件。引擎记录操作 ID、范围、旧/新非敏感引用与逐目标结果；文件采用受管内容校验和原子替换。失败恢复可恢复的受管内容，遇外部修改则停止覆盖并提示冲突。安装失败报告真实探测结果和修复方式，不承诺一键撤销任意脚本。进程中断后按操作记录与实际状态核对，不盲目重跑非幂等安装脚本。

恢复数据不含明文凭证或整份用户配置。涉及敏感原内容的恢复只允许在外部 secrets 边界处理；无法安全恢复时在执行前说明限制。持久备份单独选择、默认关闭，避免每次开关产生无期限副本。

## Rust 原生实现边界

Tauri 的 `engine_invoke` 直接调用 `engine-rs` 库，阻塞操作交给工作线程。Rust CLI 复用同一库。保留界面已有的命令、预览和结果结构，移除桌面执行对 `manage.sh`、Python 子进程和源码目录的依赖。

Rust 负责 SQLite、官方模板、安装进程、Skill 版本文件和助手配置读写。安装包只包含编译后的程序、界面和经过审查的通用资源；不复制旧引擎目录或 Python 解释器。用户安装命令可以调用 Shell，Git 集合更新可以调用 Git，这些是明确操作所需的外部程序。

最小数据关系为 Agent、安装命令、集合、资源、资源版本、Agent 分配和操作记录。分配分别保存版本与启用状态；实际生效状态由文件或程序探测，不能只看数据库 enabled。只读查询、预览和取消不创建数据库；首次明确保存或执行时初始化。旧数据库不作为新库的备用写入口。

现有 Python 代码不再承担新版功能或兼容验收。退役打包和 CI 入口时同步说明范围；工作区原有用户修改单独保留，不用批量清理覆盖。已提交历史不重写。

## 实施顺序与验收

实施者按阶段交付可运行结果，主审负责设计与独立验收；通过验收的改动按用户授权分批提交并推送 `rust` 分支。实施标签页优先使用 agy YOLO，额度耗尽后使用 kimi-ly YOLO；两者均耗尽时使用 Codex Luna（`gpt-5.6-luna`）。具体执行和清理边界见[当前任务书](goal-rust-gui.md)。下表是各阶段的完成标准，不表示已经全部实现。

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| 1：原生核心 | Rust 库、SQLite、Tauri 直接调用、预览草稿 | 重启保留修改；取消零变更；不调用 Python 或旧 Shell 引擎 |
| 2：Agent | 命令表单、官方模板、按实际来源升级 | 无需改代码新增 Agent；自定义命令执行并回读版本；无隐式迁移 |
| 3：Skill | 集合/资源/分配、版本隔离、五种操作 | 单 Agent 更新/禁用/删除互不影响；集合暂停恢复保留选择 |
| 4：MCP 与其他配置 | 服务版本、逐 Agent 分配、规则和 Hooks | 两个 Agent 配置独立；非受管内容保留；配置与连接分别回读 |
| 5：桌面交互 | 导航、动作文案、失败处理、可访问性 | 真实交互通过，文案与文件/数据库结果一致 |

### 接下来怎样推进

先完成一个能独立验收的原生闭环，再接下一类资源。现有未通过编译和审查的 Rust 文件只作为候选，不视为已实现功能，也不直接批量提交。

1. **原生存储与调用入口。** 先让 Rust 库和 CLI 完成读取、保存、重启读回；再让 Tauri 直接调用同一库。取消和演练零写入；损坏库、外来库和符号链接明确拒绝；多个进程首次保存不能丢失定义。这个阶段不扩展资源域。
2. **助手安装与升级。** 接入官方模板和自定义命令表单，保存不执行。安装、升级、卸载分别预览和执行，检查真实退出码及实际二进制状态；支持用户选择 Skill 目录和 MCP 配置格式。未知安装来源不冒充官方管理。
3. **Skills 完整流程。** 先打通一个本地集合和两个隔离助手，再增加 Git 来源。集合与逐助手技能分别验证五种操作；更新、禁用和删除当前助手的技能不能影响另一个助手；重启仍保留版本与开关。
4. **MCP、规则和 Hooks。** MCP 先覆盖本地 stdio 与远程 HTTP 定义，再验证各助手格式。规则与 Hooks 采用资源库及逐助手分配，保存内容不运行脚本。每种资源必须实际验证添加、更新、启用、禁用、删除和外部修改保护。
5. **清理旧 Python。** 用户已授权停止维护并清理旧实现。先清点代码、脚本、测试、CI、构建和文档引用；对未提交修改留存本地补丁。原生调用替换后删除旧运行入口、Python 解释器打包和双实现对照测试，再删除退役模块及专属测试。仍适用的安全检查和资源隔离用例迁入 Rust，不能随旧代码一并丢失。规则与 Skill 正文等有效资源保留。清理不触及助手安装、用户会话、凭据或外部私有仓库。
6. **独立桌面验收。** 在没有 Python、旧脚本和源码目录的隔离环境启动发行包，操作真实界面并核对 SQLite 和两个测试助手的文件。检查失败提示、焦点、滚动及小窗口；重启后再次读回。先明确验收当前 macOS 包，其它平台和签名更新分别记录，不能由本机构建推断通过。

每个闭环通过定向测试、相关回归和独立审查后单独提交并推送 `rust` 分支，核对本地、跟踪分支与远程提交一致。代码清理与行为变更分开提交。最终完成要求是上述真实操作与独立包全部满足当前交付平台标准；前端测试通过、模块文件存在或单次编译成功均不足以代表完成。
